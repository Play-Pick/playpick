## 1. 개요 (Overview)
본 프로젝트는 사용자 로그 기반의 **하이브리드 추천 시스템(Hybrid Recommendation System)**을 구축하여, 사용자에게 개인화된 공연 정보를 제공하는 것을 목표로 한다. 
**콘텐츠 기반 필터링(CBF)**의 명확한 설명 가능성과 **협업 필터링(CF)**의 유사도 매칭을 결합하여 추천 품질을 높인다.

---

## 2. 핵심 알고리즘 수식 (Scoring Formula)

각 공연에 대하여 아래의 가중 합산 점수를 계산하여 Top-N을 추출한다.

$$
Score(u, i) = \sum_{k=1}^{n} (w_k \times f_k(u, i)) + \text{Boost}(u, i)
$$

### 🛠 가중치 구성 (Weights Breakdown)
| 변수 | 요인 | 설명 | 추천 가중치($w$) |
|:---:|:---:|:---|:---:|
| **$f_1$** | **클릭/관심** | 사용자의 최근 클릭 및 찜 내역 기반 유사도 | 0.25 |
| **$f_2$** | **취향 매칭** | 선호 장르, 선호 배우 일치 여부 | 0.20 |
| **$f_3$** | **위치 근접성** | 사용자 거주지와 공연장 간의 거리/행정구역 | 0.15 |
| **$f_4$** | **대중성** | 예매율, 전체 랭킹 (Cold Start 보완) | 0.15 |
| **$f_5$** | **최신성** | 공연 시작 임박도 (Time Decay 적용) | 0.10 |
| **$f_6$** | **유사 유저** | 아이템 기반 협업 필터링 (Simple CF) | 0.15 |

## 3. 세부 점수 산출 로직 (Logic Details)

### 1️⃣ 클릭 기반 점수 ($f_{click}$) : 시간 감쇠 적용
단순 클릭 횟수가 아닌, **최근 행동에 더 높은 점수**를 부여한다.
- $f_{click} = \sum (Sim(Genre_u, Genre_i) \times \lambda^{t})$
- $\lambda$: 감쇠 계수 (예: 0.95), $t$: 경과 일수
- *의도:* 3달 전 클릭한 뮤지컬보다 어제 클릭한 연극이 현재 관심사에 가깝다.

### 2️⃣ 취향 매칭 점수 ($f_{preference}$) : 콜드 스타트 대응
가입 시 선택한 태그(분위기, 장르)와 배우 데이터를 활용한다.
- $Score = (IsGenreMatch \times 0.6) + (IsActorMatch \times 0.4)$
- 신규 유저는 가입 시 선택한 '분위기 태그(#신나는 #웅장한)' 매칭으로 대체한다.

### 3️⃣ 위치 기반 점수 ($f_{location}$) : 행정구역 우선
단순 직선거리의 한계를 보완하기 위해 행정구역 일치를 최우선으로 본다.
```python
if user.gu == theater.gu:
    score = 1.0
else:
    score = max(0, 1 - distance(user, theater) / 20km)
```

### 4️⃣ 유사 유저/공연 점수 ($f_{cf}$) : Lite Collaborative Filtering
"이 공연을 본 사람들이 같이 본 공연" 데이터를 활용한다. (아이템 기반 협업 필터링)

복잡한 행렬 연산 대신 자카드 유사도(Jaccard Similarity) 활용

$$
J(A, B) = \frac{|User_A \cap User_B|}{|User_A \cup User_B|}
$$

**구현:** 배치 작업(Batch)으로 미리 연관 공연 테이블을 생성해 둔다.

### 5️⃣ 최신성/임박 점수 ($f_{recency}$) : 마감 임박 효과
공연 시작일이 가까울수록 점수가 급격히 상승한다 (지수 함수).

$$
f_{recency} = \frac{1}{1 + e^{k \cdot (days - threshold)}}
$$

**효과:** "마감 임박" 심리를 자극하여 클릭률 유도.

## 4. 시스템 아키텍처 (Architecture)

### 🏗 데이터베이스 모델링 (ERD 핵심)

- **User:** `id`, `location(gu, dong)`, `preference_tags`, `fav_actors`
- **Performance:** `id`, `title`, `genre`, `actors`, `location`, `start_date`, `score_static`(인기/최신성 미리 계산)
- **UserLog:** `user_id`, `performance_id`, `action_type(view/like)`, `timestamp`
- **Rec_Candidate (Cache):** `user_id`, `performance_id_list`, `update_time`

**핵심:** 실시간 연산을 줄이기 위해 유저별 추천 후보군을 주기적으로 저장.

---

### ⚙️ 처리 프로세스 (Pipeline)

#### Offline (매일 새벽 / 배치):
1. 전체 공연의 대중성($f_4$), 최신성($f_5$) 점수 갱신.
2. 아이템 간 유사도($f_6$) 계산 및 연관 테이블 생성.

#### Online (유저 접속 시 / 실시간):
1. 유저의 위치, 선호 장르 필터링으로 후보군(Candidate) 1차 선정 (약 100~300개).
2. 후보군에 대해 가중치 공식($Score(u, i)$) 적용 및 정렬.
3. Top 10 리스트 반환.

## 5. 차별화 포인트 (UX/UI Features)

### 🌟 추천 사유 시각화 (Explainable AI)
사용자에게 단순히 결과만 던지지 않고 **"왜?"**를 설명한다. 가장 높은 점수를 기록한 요인($f_k$)을 텍스트로 변환하여 카드에 표시한다.

**Example UI Message:**
- $f_3$ High: "🏠 OOO님 집 근처(강남구)에서 열리는 공연이에요!"
- $f_2$ High: "❤️ 선호하시는 '조승우' 배우의 신작입니다."
- $f_6$ High: "👀 비슷한 취향의 유저들이 많이 예매했어요."

---

### 📊 육각형 스탯 차트 (Radar Chart)
공연 상세 페이지에서 해당 공연의 매력 포인트를 차트로 제공한다.

**축:** 대중성, 접근성(거리), 가격합리성, 취향일치도, 화제성

## 6. 구현 및 최적화 전략 (Implementation)

- **Python Pandas 활용:** 벡터 연산을 통해 루프(Loop) 없이 고속으로 점수 계산.
- **Denormalization (반정규화):** 조인(Join) 연산을 줄이기 위해 Performance 테이블에 `actor_names_string` 등의 검색용 컬럼 추가.
- **Filter Bubble 방지:** 추천 결과 10개 중 1~2개는 점수와 무관하게 "새로운 발견(Serendipity)" 라벨을 붙여 랜덤한 고평점 장르를 노출.
