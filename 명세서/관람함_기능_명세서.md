## 1. 기능 개요

### 1.1 목적
사용자가 이미 관람한 공연을 기록하고 관리할 수 있는 기능을 제공합니다. 이를 통해:
- 관람 이력 관리 및 확인
- 추천 시스템에 관람 기록 반영 (UserLog 자동 생성)
- 마이페이지에서 관람한 공연 목록 조회
- 공연 상세 페이지에서 관람 여부 표시 및 토글

### 1.2 주요 기능
- **관람함 추가**: 공연 상세 페이지의 "봤어요" 버튼으로 관람 기록 추가
- **관람함 해제**: "관람함" 버튼 클릭으로 기록 삭제
- **관람 목록 조회**: 마이페이지에서 전체 관람 이력 확인
- **자동 추천 로그**: 관람 기록 시 추천 시스템에 자동으로 시그널 전송

### 1.3 사용자 플로우
```
1. 사용자가 공연 상세 페이지 접속
   ↓
2. HeaderSection에 "봤어요" 또는 "관람함" 버튼 표시
   ↓
3. 버튼 클릭 시 watchedStore.addToWatched() 또는 removeFromWatched() 호출
   ↓
4. API 요청: POST/DELETE /api/performances/{mt20id}/watch/
   ↓
5. 백엔드: WatchedPerformance 레코드 생성/삭제
   ↓
6. 프론트엔드: 버튼 상태 업데이트 (낙관적 업데이트)
   ↓
7. 마이페이지에서 관람 목록 확인 가능
```

## 2. 데이터베이스 설계

### 2.1 WatchedPerformance 모델

**파일 위치**: `back/accounts/models.py` (lines 150-193)

```python
class WatchedPerformance(models.Model):
    """사용자 관람 공연 기록"""

    user = models.ForeignKey(
        User,
        on_delete=models.CASCADE,
        related_name='watched_performances',
        verbose_name="사용자"
    )

    performance = models.ForeignKey(
        'performances.Performance',
        on_delete=models.CASCADE,
        to_field='mt20id',  # 중요: mt20id를 참조 (id가 아님)
        related_name='watched_by_users',
        verbose_name="공연"
    )

    watched_at = models.DateTimeField(
        auto_now_add=True,
        verbose_name="관람 등록 시각"
    )

    rating = models.SmallIntegerField(
        null=True,
        blank=True,
        verbose_name="별점 (1-5)",
        help_text="향후 별점 기능 확장용"
    )

    class Meta:
        verbose_name = "관람한 공연"
        verbose_name_plural = "관람한 공연 목록"
        unique_together = [['user', 'performance']]  # 중복 방지
        indexes = [
            models.Index(fields=['user', 'watched_at']),
            models.Index(fields=['-watched_at']),  # 최신순 정렬용
        ]
        ordering = ['-watched_at']  # 기본 정렬: 최신순

    def __str__(self):
        return f"{self.user.username} - {self.performance.prfnm}"
```

### 2.2 주요 설계 포인트

#### to_field='mt20id' 사용 이유
Performance 모델은 `mt20id` (CharField)를 실질적인 식별자로 사용합니다. Django의 기본 auto-increment `id` 대신 KOPIS API의 고유 ID인 `mt20id`를 참조해야 하므로 `to_field='mt20id'`를 명시합니다.

```python
# Performance 모델 (참고)
class Performance(models.Model):
    mt20id = models.CharField(max_length=20, primary_key=True)
    prfnm = models.CharField(max_length=200)
    # ...
```

#### unique_together 제약
한 사용자가 동일한 공연을 여러 번 관람함에 추가하는 것을 방지합니다. API에서는 `get_or_create()`를 사용하여 중복 요청을 idempotent하게 처리합니다.

#### rating 필드 (확장용)
현재는 사용하지 않지만, 향후 사용자가 관람한 공연에 별점을 매기는 기능을 추가할 수 있도록 미리 설계되었습니다.

#### 3.1.1 관람 목록 조회

```http
GET /api/performances/watched/
Authorization: Bearer {access_token}
```

**응답 예시** (200 OK):
```json
[
  {
    "mt20id": "PF123456",
    "prfnm": "뮤지컬 <위키드>",
    "poster": "http://www.kopis.or.kr/upload/pfmPoster/PF_123456.gif",
    "genrenm": "뮤지컬",
    "fcltynm": "샤롯데씨어터",
    "prfpdfrom": "2024-01-15",
    "prfpdto": "2024-06-30",
    "prfstate": "공연중",
    "is_watched": true,
    "watched_at": "2024-11-20T15:30:00Z"
  },
  // ...
]
```

**구현 코드**:
```python
@action(detail=False, methods=['get'], permission_classes=[IsAuthenticated])
def watched(self, request):
    """
    사용자가 관람한 공연 목록 조회
    GET /api/performances/watched/
    """
    from accounts.models import WatchedPerformance

    user = request.user

    # 관람한 공연 조회 (최신순)
    watched_records = WatchedPerformance.objects.filter(
        user=user
    ).select_related('performance')

    # Performance 객체 추출
    performances = [record.performance for record in watched_records]

    # 직렬화
    serializer = self.get_serializer(performances, many=True)
    return Response(serializer.data)
```

#### 3.1.2 관람함 추가/해제 (통합 엔드포인트)

```http
POST /api/performances/{mt20id}/watch/
Authorization: Bearer {access_token}
```

**응답 예시** (200 OK):
```json
{
  "success": true,
  "is_watched": true,
  "watched_at": "2024-11-20T15:30:00Z"
}
```

```http
DELETE /api/performances/{mt20id}/watch/
Authorization: Bearer {access_token}
```

**응답 예시** (200 OK):
```json
{
  "success": true,
  "is_watched": false,
  "deleted": true
}
```

**구현 코드**:
```python
@action(detail=True, methods=['post', 'delete'], permission_classes=[IsAuthenticated], url_path='watch')
def watch(self, request, pk=None):
    """
    공연 관람함 추가/해제
    POST /api/performances/{mt20id}/watch/ - 추가
    DELETE /api/performances/{mt20id}/watch/ - 해제
    """
    from accounts.models import WatchedPerformance

    performance = self.get_object()
    user = request.user

    if request.method == 'POST':
        # 관람함 추가
        watched_record, created = WatchedPerformance.objects.get_or_create(
            user=user,
            performance=performance
        )

        # 추천 시스템 로그 저장 (새로 생성된 경우만)
        if created:
            from recommendations.models import UserLog
            UserLog.objects.create(
                user=user,
                performance=performance,
                action_type='view'
            )

        return Response({
            'success': True,
            'is_watched': True,
            'watched_at': watched_record.watched_at
        })

    elif request.method == 'DELETE':
        # 관람함 해제
        deleted_count, _ = WatchedPerformance.objects.filter(
            user=user,
            performance=performance
        ).delete()

        return Response({
            'success': True,
            'is_watched': False,
            'deleted': deleted_count > 0
        })
```

### 3.2 핵심 설계 결정

#### 3.2.1 단일 엔드포인트 vs 별도 엔드포인트

**초기 설계 (문제 발생)**:
```python
# 405 에러 발생 원인
@action(detail=True, methods=['post'], url_path='watch')
def watch(self, request, pk=None):
    # ...

@action(detail=True, methods=['delete'], url_path='watch')
def unwatch(self, request, pk=None):
    # ...
```

**문제**: Django REST Framework는 동일한 `url_path`를 가진 @action 중 마지막 것만 등록합니다. 따라서 POST 요청 시 405 Method Not Allowed 에러가 발생했습니다.

**해결책**: 단일 액션에서 `methods=['post', 'delete']`로 통합
```python
@action(detail=True, methods=['post', 'delete'], url_path='watch')
def watch(self, request, pk=None):
    if request.method == 'POST':
        # 추가 로직
    elif request.method == 'DELETE':
        # 삭제 로직
```

#### 3.2.2 Idempotent POST 요청

`get_or_create()`를 사용하여 중복 요청을 안전하게 처리합니다:
```python
watched_record, created = WatchedPerformance.objects.get_or_create(
    user=user,
    performance=performance
)
```

- **created=True**: 새로 생성된 경우 → UserLog 추가
- **created=False**: 이미 존재하는 경우 → 중복 요청, UserLog 추가하지 않음

#### 3.2.3 추천 시스템 연동

관람함 추가 시 자동으로 추천 시스템에 시그널 전송:
```python
if created:
    from recommendations.models import UserLog
    UserLog.objects.create(
        user=user,
        performance=performance,
        action_type='view'
    )
```

이를 통해 사용자의 관람 기록이 개인화 추천에 반영됩니다.

```javascript
import apiClient from './axios'

const normalizeResponse = (response) => {
  if (!response) return []
  if (Array.isArray(response)) return response
  if (Array.isArray(response.data)) return response.data
  if (Array.isArray(response.data?.results)) return response.data.results
  if (Array.isArray(response.data?.data)) return response.data.data
  return []
}

export default {
  /**
   * 관람한 공연 목록 조회
   * GET /api/performances/watched/
   */
  fetchWatched() {
    return apiClient.get('/performances/watched/')
  },

  /**
   * 공연 관람함 추가
   * POST /api/performances/{mt20id}/watch/
   */
  addWatched(performanceId) {
    return apiClient.post(`/performances/${performanceId}/watch/`)
  },

  /**
   * 공연 관람함 해제
   * DELETE /api/performances/{mt20id}/watch/
   */
  removeWatched(performanceId) {
    return apiClient.delete(`/performances/${performanceId}/watch/`)
  },

  normalizeResponse,
}
```

### 4.2 Pinia Store

**파일**: `front/src/stores/watchedStore.js`

```javascript
import { defineStore } from 'pinia'
import { ref } from 'vue'
import watchedAPI from '@/api/watched'

const normalizePerformance = (item) => {
  const source = item?.performance || item
  const mt20id = source?.mt20id || source?.id || source?.performance_id
  return {
    ...source,
    mt20id,
    prfnm: source?.prfnm || source?.title || source?.name || source?.performance_name,
    poster: source?.poster || source?.poster_url || source?.image,
    fcltynm: source?.fcltynm || source?.venue || source?.place,
    prfpdfrom: source?.prfpdfrom || source?.start_date || source?.startDate,
    prfpdto: source?.prfpdto || source?.end_date || source?.endDate,
    genrenm: source?.genrenm || source?.genre,
    is_watched: source?.is_watched ?? true
  }
}

const normalizeWatched = (payload) => {
  const list = watchedAPI.normalizeResponse(payload)
  return list.map(normalizePerformance)
}

export const useWatchedStore = defineStore('watched', () => {
  const items = ref([])
  const loading = ref(false)
  const errorMessage = ref('')

  const fetchWatched = async () => {
    loading.value = true
    errorMessage.value = ''
    try {
      const response = await watchedAPI.fetchWatched()
      items.value = normalizeWatched(response)
      return items.value
    } catch (err) {
      const status = err?.response?.status
      if (status === 401 || status === 404) {
        items.value = []
        return items.value
      }
      errorMessage.value = err?.response?.data?.detail || err?.message || '관람한 공연 목록을 불러오지 못했어요.'
      throw err
    } finally {
      loading.value = false
    }
  }

  const addToWatched = async (performanceId) => {
    errorMessage.value = ''
    try {
      await watchedAPI.addWatched(performanceId)
      // 낙관적 업데이트: 전체 목록을 다시 불러오지 않고 클라이언트에서 추가
      // 실제 데이터는 fetchWatched() 호출 시 서버에서 받아옴
      return true
    } catch (err) {
      const status = err?.response?.status
      if (status === 401 || status === 404) {
        return false
      }
      errorMessage.value = err?.response?.data?.detail || err?.message || '관람함 추가에 실패했습니다.'
      throw err
    }
  }

  const removeFromWatched = async (performanceId) => {
    errorMessage.value = ''
    try {
      await watchedAPI.removeWatched(performanceId)
    } catch (err) {
      const status = err?.response?.status
      if (status === 401 || status === 404) {
        items.value = []
        return
      }
      errorMessage.value = err?.response?.data?.detail || err?.message || '관람함 삭제에 실패했습니다.'
      throw err
    }

    // 로컬 상태에서 제거
    const targetId = String(performanceId)
    items.value = items.value.filter((item) => {
      const itemId = String(item.mt20id || item.id || '')
      return itemId !== targetId
    })
  }

  const isWatched = (performanceId) => {
    const targetId = String(performanceId)
    return items.value.some((item) => {
      const itemId = String(item.mt20id || item.id || '')
      return itemId === targetId
    })
  }

  return {
    items,
    loading,
    errorMessage,
    fetchWatched,
    addToWatched,
    removeFromWatched,
    isWatched
  }
})
```

#### 4.3.2 PerformanceDetailView 토글 로직

**파일**: `front/src/views/PerformanceDetailView.vue` (lines 306-330)

```vue
<script setup>
import { useWatchedStore } from '@/stores/watchedStore'

const watchedStore = useWatchedStore()
const watchedLoading = ref(false)

const handleToggleWatched = async () => {
  if (!currentPerformance.value?.mt20id) return

  watchedLoading.value = true
  try {
    const isCurrentlyWatched = watchedStore.isWatched(currentPerformance.value.mt20id)

    if (isCurrentlyWatched) {
      // 관람함 해제
      await watchedStore.removeFromWatched(currentPerformance.value.mt20id)
      currentPerformance.value.is_watched = false
    } else {
      // 관람함 추가
      await watchedStore.addToWatched(currentPerformance.value.mt20id)
      currentPerformance.value.is_watched = true
    }
  } catch (err) {
    if (err.message === '로그인이 필요합니다.' || err?.response?.status === 401) {
      alert('로그인이 필요한 기능입니다.')
    } else {
      console.error('관람함 토글 실패:', err)
      alert(err.message || '관람함 처리 중 오류가 발생했습니다.')
    }
  } finally {
    watchedLoading.value = false
  }
}
</script>

<template>
  <HeaderSection
    :performance="currentPerformance"
    :watched-loading="watchedLoading"
    @toggle-watched="handleToggleWatched"
  />
</template>
```

## 5. 에러 해결 과정

### 5.1 에러 #1: 405 Method Not Allowed

#### 증상
```
AxiosError: Request failed with a false node 405
POST /api/performances/PF123456/watch/
```

사용자가 공연 상세 페이지에서 "봤어요" 버튼 클릭 시 405 에러 발생.

#### 원인 분석

**초기 코드** (`back/performances/api_views.py`):
```python
@action(detail=True, methods=['post'], permission_classes=[IsAuthenticated], url_path='watch')
def watch(self, request, pk=None):
    """관람함 추가"""
    # ...

@action(detail=True, methods=['delete'], permission_classes=[IsAuthenticated], url_path='watch')
def unwatch(self, request, pk=None):
    """관람함 해제"""
    # ...
```

**문제**: Django REST Framework의 ViewSet은 동일한 `url_path`를 가진 `@action` 데코레이터가 여러 개 있을 경우, **마지막에 정의된 액션만 라우팅 테이블에 등록**합니다.

따라서:
1. `watch` 액션 (POST) 등록 시도
2. `unwatch` 액션 (DELETE) 등록 시 **같은 url_path='watch'**이므로 이전 등록을 덮어씀
3. 최종적으로 `DELETE /api/performances/{mt20id}/watch/`만 등록됨
4. `POST` 요청 시 405 Method Not Allowed 반환

#### 해결 방법

**수정된 코드**:
```python
@action(detail=True, methods=['post', 'delete'], permission_classes=[IsAuthenticated], url_path='watch')
def watch(self, request, pk=None):
    """
    공연 관람함 추가/해제
    POST /api/performances/{mt20id}/watch/ - 추가
    DELETE /api/performances/{mt20id}/watch/ - 해제
    """
    from accounts.models import WatchedPerformance

    performance = self.get_object()
    user = request.user

    if request.method == 'POST':
        # 관람함 추가 로직
        watched_record, created = WatchedPerformance.objects.get_or_create(
            user=user,
            performance=performance
        )

        if created:
            from recommendations.models import UserLog
            UserLog.objects.create(
                user=user,
                performance=performance,
                action_type='view'
            )

        return Response({
            'success': True,
            'is_watched': True,
            'watched_at': watched_record.watched_at
        })

    elif request.method == 'DELETE':
        # 관람함 해제 로직
        deleted_count, _ = WatchedPerformance.objects.filter(
            user=user,
            performance=performance
        ).delete()

        return Response({
            'success': True,
            'is_watched': False,
            'deleted': deleted_count > 0
        })
```

**핵심 변경사항**:
- `methods=['post', 'delete']`로 두 HTTP 메서드를 단일 액션에서 처리
- `request.method`로 분기하여 로직 구분
- 동일한 `url_path='watch'`를 공유하면서 405 에러 해결

## 9. FAQ

### Q1: "봤어요" 버튼 클릭 시 아무 반응이 없어요.

**A**: 다음을 확인해주세요:
1. 로그인 상태 확인 (비로그인 시 Alert 표시되어야 함)
2. 브라우저 콘솔에서 에러 확인 (F12 > Console)
3. Network 탭에서 API 요청 실패 여부 확인
4. 백엔드 서버 실행 상태 확인

### Q2: 관람함에 추가했는데 마이페이지에 안 나와요.

**A**:
1. 마이페이지 새로고침 (F5)
2. 브라우저 캐시 삭제 후 재접속
3. 다른 계정으로 로그인한 건 아닌지 확인
4. 백엔드에서 직접 확인:
   ```bash
   python manage.py shell
   >>> from accounts.models import WatchedPerformance
   >>> WatchedPerformance.objects.filter(user__username='your_username')
   ```

### Q3: 관람함 해제가 안 돼요.

**A**:
1. 네트워크 연결 확인
2. 콘솔 에러 메시지 확인
3. DELETE 요청이 서버로 전송되는지 Network 탭에서 확인
4. 백엔드 권한 문제 확인 (IsAuthenticated)

### Q4: 마이그레이션 적용 시 에러가 나요.

**A**:
```bash
# 마이그레이션 충돌 확인
python manage.py showmigrations accounts

# 마이그레이션 리셋 (주의: 데이터 손실 가능)
python manage.py migrate accounts zero
python manage.py migrate accounts

# 마이그레이션 파일 재생성
rm accounts/migrations/0005_*.py
python manage.py makemigrations accounts
python manage.py migrate accounts
```

### Q5: 프로덕션 배포 후 404 에러가 나요.

**A**:
1. Nginx/Apache 설정에서 API 프록시 확인
2. Django ALLOWED_HOSTS 설정 확인
3. CORS 설정 확인 (django-cors-headers)
4. URL 라우팅 확인:
   ```bash
   python manage.py show_urls | grep watch
   ```
