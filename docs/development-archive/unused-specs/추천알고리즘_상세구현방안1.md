# 🎭 SSAFY 1학기 관통 프로젝트: 추천 시스템 개발 명세서 (Final)

## 1. 개요 (Overview)
본 문서는 사용자 로그 기반의 **하이브리드 추천 시스템(Hybrid Recommendation System)** 구현을 위한 아키텍처, DB 설계, 및 프론트엔드/백엔드 역할 분담을 기술한다.

### 🏗 아키텍처 결정사항
- **방식:** 분리형 앱 구조 (Separated App)
- **앱 이름:** `recommendations` (신규 생성)
- **이유:**
  - 기존 `performances` 앱의 비대화 방지 (SRP 원칙 준수)
  - 추천 로직 수정 시 핵심 도메인 코드 영향 최소화
  - 순환 참조 방지 및 유지보수 용이성 확보

## 2. 데이터베이스 설계 (ERD Changes)

### 📌 1. Accounts (User 모델 확장)
기존 `accounts_user` 테이블에 추천 알고리즘($f_2, f_3$)을 위한 필드 추가
- `region_gu` (String): 거주지 구 (위치 기반 추천용)
- `region_dong` (String): 거주지 동
- `preference_tags` (JSON): 선호 장르 태그 리스트
- `favorite_actors` (JSON): 선호 배우 리스트
- `birth_date` (Date): 연령대 필터링용

### 📌 2. Recommendations (신규 모델)
**A. UserLog (행동 로그)**
사용자의 모든 행동을 기록하여 $f_1$(Time Decay) 점수 계산에 활용
- `user`: FK (User)
- `performance`: FK (Performance)
- `action_type`: 'view'(1점), 'like'(3점), 'search'(2점)
- `timestamp`: 생성 일시 (최신순 정렬용)

**B. PerformanceMetric (공연 통계 캐시)**
배치 작업으로 미리 계산된 공연별 점수 저장 ($f_4, f_5, f_6$)
- `performance`: OneToOne (Performance)
- `score_popularity`: 대중성 점수
- `score_recency`: 최신성 점수
- `similar_performances`: JSON (유사 공연 ID 리스트)

**C. RecommendationCache (결과 캐시)**
실시간 연산 부하를 줄이기 위해 유저별 추천 결과 저장
- `user`: OneToOne (User)
- `top_n_list`: JSON (추천된 공연 ID 목록)
- `updated_at`: 갱신 일시

## 3. 📝 Backend 개발 체크리스트 (Django)

### ✅ Step 1: 앱 설정 및 모델링
- [ ] `python manage.py startapp recommendations` 실행
- [ ] `settings.py`에 앱 등록
- [ ] `recommendations/models.py`에 `UserLog`, `PerformanceMetric`, `RecommendationCache` 작성
- [ ] `accounts/models.py`에 User 필드 추가 후 Migration 진행

### ✅ Step 2: 추천 엔진 구현 (`recommendations/engine.py`)
- [ ] **RecommendationEngine 클래스** 생성
- [ ] **점수 산출 메서드($f_1 \sim f_6$)** 구현
  - $f_1$: 로그 기반 Time Decay 적용
  - $f_2$: User 태그/배우와 공연 정보 매칭
  - $f_3$: 거주지(Gu) 일치 여부 확인
  - $f_4$: 예매율/랭킹 정규화 점수 반영
- [ ] **Top-N 추출 메서드** 구현 (후보군 필터링 -> 점수 계산 -> 정렬)

### ✅ Step 3: API 개발 (`recommendations/views.py`)
- [ ] **로그 저장 API** (`POST /api/recommendations/log/`)
  - 상세 페이지 진입 시, 찜하기 시 호출
- [ ] **추천 목록 조회 API** (`GET /api/recommendations/list/`)
  - 캐시 확인 -> 없으면 Engine 호출 -> 결과 반환

### ✅ Step 4: 배치 작업 (Optional)

  - 매일 새벽 공연들의 최신성/대중성 점수 갱신
